## 실패 1건의 원인

Foundation-Sec의 `so-back-206-benign`이 ERROR다. 원본 응답에서 `done_reason=length`, `eval_count=64`, 최종 `content`는 빈 문자열이고 thinking 필드가 존재한다. 출력 예산을 소진해 유효한 판정 JSON이 없는 상태다. 지연3.804초, 시도1회이며 네트워크 재시도는 없다.

현재 파서는 JSON 파싱을 먼저 수행하므로 저장 오류명은 `PARSE_ERROR`다. 원본의 length 정보까지 고려하면 출력 한도 소진으로 설명되는 실패다. 오류명을 더 구체적으로 표시하려면 length 검사를 앞에 두는 수정이 필요하다. 이번 분석에서는 제품 코드를 변경하지 않았다.

이 물리적 요청 실패1건이 Foundation-Sec + Jev에도 ERROR/null로 전파됐다. 전체100개 구성 결과 기준 SUCCESS98/ERROR2지만, 독립적으로 두 요청이 실패한 것은 아니다. 기술적 실패를 NORMAL이나 REVIEW로 바꾼 흔적은 없다. 전체 실험 COMPLETED는 작업 종료를 뜻하며 모든 요청 성공을 뜻하지 않는다.
