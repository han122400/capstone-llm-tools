# Thinking 평가 예산 개선

## 구현 계획

1. 컨텍스트/출력 예산을 함께 검증하고 설정 UI의 고정 컨텍스트 제한을 해제한다.
2. Qwen thinking 시험용 설정(컨텍스트 8192, 총 출력 4096, timeout 480초)을 한 번에 선택할 수 있게 한다. 자동 평가 없이 설정만 저장한다.
3. 출력 소진을 OUTPUT_LIMIT로 기록하고 실제 설정·예산을 새 실험에 보존한다. 이전 실험은 수정하지 않는다.
4. 네트워크 모의 응답으로 한도·요청 옵션·스냅샷을 검증하고 전체 백엔드/타입/빌드/브라우저 테스트를 실행한다.

## 설계 범위

- 출력 예약량은 thinking과 최종 JSON이 함께 사용하는 총 상한이다. 4096에서도 완료 또는 정확도 개선을 보장하지 않는다.
- 공통 입력은 기존 최대 3000 UTF-8 바이트 제한을 유지한다. 바이트를 보수적 토큰 상한으로 사용하며 템플릿 여유 512를 예약한다. 실제 모델의 system/messages도 어댑터에서 추가 검사하며 자동 절단하지 않는다.
- 설정 저장 시 입력 공간이 없는 조합은 거부한다. 모델의 지원 컨텍스트는 기존 /api/show 사전 검사에서 확인한다.
- 두 로컬 모델의 공통 컨텍스트·출력 예산이며 동시 실행 제한은 1이다. Jev에는 이 로컬 옵션을 전달하지 않는다.
- thinking OFF/ON 비교 시 같은 컨텍스트·출력·timeout·데이터·프롬프트를 유지한다. 과거 4096/1024 결과와 새 결과는 조건이 다르다.
- 480초는 기존 약 76초/1024토큰 관측을 바탕으로 긴 추론을 허용하는 시험값이다. 서버 상태·RAM 증가·속도·정확도는 실제 평가 전 미검증이다.

## 구현 및 검증 결과 (2026-10-15)

- 설정 화면에서 컨텍스트 4096–65536, 출력 16–8192 편집과 시험 설정 채우기를 지원한다. 저장 시 기존 값과 부분 변경을 합쳐 입력 공간을 검증한다. 환경변수/과거 저장값에서 유입된 잘못된 예산도 새 평가 시작 전에 차단한다.
- 예산 버전 `utf8-reserve-v2`: 기존 512 템플릿 여유에 경계 여유 1을 추가하여 공통 한도와 어댑터의 엄격한 `< context` 검사를 일치시킨다. 프롬프트 v3 / 8192 / 4096에서 공통 입력은 2029 UTF-8 바이트다. 프롬프트 내용은 변경하지 않았다.
- `done_reason=length`는 최종 JSON이 비어 있어도 `OUTPUT_LIMIT`로 기록한다. 기술적 실패를 정상 판정으로 바꾸거나 동일 예산으로 재시도하지 않는다. 원본 응답과 시도 이력은 유지한다.
- 새 실험 환경에 고정된 4096 대신 선택한 컨텍스트와 예산 세부 내용을 기록한다. 기존 실험 스냅샷에는 소급 적용하지 않는다.
- 새 회귀 테스트 6개가 수정 전 모두 실패함을 확인한 뒤 수정했다. 전체 Pytest **134 passed (17.22s)**. TypeScript 검사 통과. Next.js 프로덕션 빌드 통과. Playwright 전체 **15 passed (1.2m)**: 1280px/390px 설정 채우기·저장·새로고침·잘못된 조합 차단 포함. 일반 테스트는 임시 DB 및 모의 응답만 사용했다.
- 실제 Ollama `/api/show` 메타데이터 조회만 수행했다. 설치된 Qwen은 `qwen35.context_length=262144`, `thinking.values=[false,true]`를 보고했다. 이는 실제 8192 컨텍스트 추론 완료·메모리·정확도 검증이 아니다.
- 비활성 상태에서 프로젝트 백엔드를 갱신하고 설정 API에 8192/4096/480/ON을 저장했다. 기존 실제 실험 7건의 전체 조회 결과가 변경 전후 동일함을 확인했다. 프론트엔드 프록시에서도 새 값을 확인했다. 추가 실제 평가는 0건이다.

## 다음 평가

브라우저를 새로고침하고 설정에서 8192 / 4096 / 480초 / Qwen ON을 확인한다. 개발 20건으로 **새 실험**을 시작한다. 실패 항목 재실행은 이전 예산을 보존하므로 이번 비교에 사용하지 않는다. OFF 기준선도 새 예산을 유지한 채 thinking만 OFF로 바꿔 별도 실험을 실행한다. 완료율·OUTPUT_LIMIT·TIMEOUT·자동 판정률·탐지율·처리 시간·메모리 모두 비교한다. 실제 평가는 사용자가 시작한다.
