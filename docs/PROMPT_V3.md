# 프롬프트 v3 적용 계획 및 검증

## 범위

2026-10-15. 공통 판정 기준을 `email-injection-choice-v3`로, 같은 기준을 사용하는 Jev 재검토 질문을 `email-injection-jev-review-v2`로 변경한다. 기존 결과의 프롬프트 스냅샷과 결합 정책은 보존한다. 룰 탐지, 작업·권한 맥락 필드, 실제 평가 실행은 이번 변경에 포함하지 않는다.

## 구현 순서

1. 요청 어댑터·설정 API·저장 결과의 버전 및 공통 기준 전달 테스트를 확장한다. v1/v2 과거 기록 보존과 현재 단독·2단계 구성의 버전을 검증한다.
2. 교육·신고용 인용과 실제 지시의 구별 → 명확한 작업/권한 우회 → 구체적 유도가 있으나 판단 맥락이 부족한 REVIEW → 일반 업무 NORMAL 순서를 추가한다. 일반 회신·승인 언급만으로 공격으로 간주하지 않되 이메일 주장을 승인 절차 우회 근거로 사용하는지는 별도로 판단한다.
3. Jev 재검토에서 예비 판정과의 일치·불일치 자체는 근거가 아님을 명시한다. 프롬프트 길이와 4096컨텍스트/1024출력 예산을 검증한다.
4. 비용 없는 백엔드·필요 브라우저 검증을 실행하고, 실행 중인 평가가 없는 경우 로컬 백엔드에 적용된 버전을 확인한다.

## 평가 해석

자동 테스트는 요청 형식·버전·데이터 보존을 검증한다. 실제 오탐·미탐 감소는 입증하지 않는다. 작업 맥락이 없는 입력의 한계는 남는다. 후속 실제 평가는 사용자가 개발셋에서 시작하며 오탐·미탐·REVIEW·자동 판정률을 함께 비교한다. 최종 평가 정답에 맞춰 사례나 기준을 조정하지 않는다.

## 적용 결과

- 공통 지시문에 판정 순서를 추가했다. 교육·신고·분석용 인용과 실제 AI 지시를 구분하고, 승인·정책 주장 자체와 이를 이용한 지시/승인 절차 우회를 구분한다.
- NORMAL은 일반 회신 요청과 승인 사실 언급을 허용하면서 별도의 권한 우회 검사를 요구한다. INJECTION은 역할·지시·출력·권한의 실제 변경 유도를 기준으로 삼고, 허용되지 않은 행동 요청만으로 공격을 확정하지 않는다.
- REVIEW는 구체적인 작업·권한 유도가 있지만 신뢰된 맥락이 없어 정당성을 판단하기 어려운 경우로 한정한다. 키워드나 맥락 부재만으로 REVIEW를 선택하지 않으며, 기술적 실패는 여전히 별도 상태다.
- Jev 재검토 질문에는 예비 판정과 일치한다는 사실 자체가 정확성의 증거가 아니라는 지시를 추가했다. Jev 단독·재검토·두 로컬 모델은 같은 공통 지시와 판정 기준을 사용한다. 2단계 최종 정책은 `local-then-jev-final-v1` 그대로다.
- 입력 생성, 정답 라벨, 데이터셋, 추론 설정은 수정하지 않았다. v1/v2 및 과거 재검토 v1 스냅샷은 그대로 조회된다.

## 길이와 입력 예산

로컬 시스템 프롬프트 UTF-8 크기는 v2의1633바이트에서 v3의1554바이트로 줄었다. 4096컨텍스트/템플릿 여유512/출력1024 기준 공통 입력 제한은927→1006바이트다. 출력64에서는1966바이트다. 실제 토크나이저나 원격 Jev 컨텍스트 한도 검증은 아니다.

기존 공개 개발20건의 최대 입력851바이트, 평가100건의 최대856바이트로 모두1006바이트 이내임을 확인했다. 평가100건은 입력 크기만 검사했고 추론하지 않았다. 본문을 자르거나 변환하지 않았다.

## 실제 실행한 검증 (2026-10-15)

1. v3 적용 전 확장한 계약 테스트4개가 v2 버전으로 실패함을 확인하고, 구현 후4개 모두 통과했다.
2. 전체 백엔드: `cd backend; ..\.venv\Scripts\python.exe -m pytest -q` → **128 passed** (24.57초). 실제 HTTP 대신 MockTransport, 임시 DB와 DEMO를 사용한다. 과거 v1/v2 기록 보존, 새로운 2차 질문 버전 저장, 메타데이터 제외, 동일 이메일 전달 및 출력1024 설정을 포함한다.
3. 프론트엔드: `npm.cmd run typecheck` 통과. 실행 중인 앱과 분리한 `.next-cascade-build`에서 `npm.cmd run build` 통과. Next가 추가한 검증용 tsconfig include 두 항목은 검사 후 제거했다.
4. `npm.cmd run test:e2e` → **15 passed** (2.0분). 별도8101/3101 서버·임시 데이터·DEMO를 사용했다. 데스크톱/모바일 프롬프트 원문 조회, v3 통계 필터, 기존 이력과 워크플로를 검증했다. NO_COLOR/FORCE_COLOR 환경 경고 외 테스트 실패는 없다.
5. 개발20건 × 현재5개 구성의 임시 DB mock 평가: 최종100행+Jev재검토40행=140행 SUCCESS, 실제 모델/API 호출0. 결과는 [PROMPT_V3_VERIFICATION.json](PROMPT_V3_VERIFICATION.json)에 기록했다. mock 성공은 탐지 정확도 검증이 아니다.
6. 실제/DEMO 진행 중인 실험이 없음을 확인한 후 이 프로젝트의8001 백엔드만 재시작했다.8001 API와3001 프론트엔드 경유 설정 조회 모두 단독v3/재검토v2를 반환하며 출력1024와 입력1006 설정을 확인했다. 설정·모델 연결 확인·실제 평가 POST는 하지 않았다.

## 사용 순서

대시보드를 새로고침하고 설정의 모델 판정 프롬프트에서 `email-injection-choice-v3`를 확인한다. 개발20건을 선택해 이전과 같은 모델·thinking·출력 제한·실행 모드로 새 실험을 실행한다. Jev 재검토 질문은 `email-injection-jev-review-v2`로 기록된다. 현재 2단계 구성과 과거 독립 합의 결합을 동일한 방식으로 비교하지 않는다. 오탐·미탐 감소와 REVIEW/자동 판정률 변화는 실제 결과가 나온 뒤 판단한다.
